# 도마뱀 성장·급여 일지 웹앱 — 계획서 (v0.1)

## 1. 범위

| 단계 | 내용 | 상태 |
|---|---|---|
| **Phase 1 (지금)** | 웹 + iPhone PWA, 수동 입력, 자동 계산, 다음 급여일, 온습도 이모지, 엑셀 내보내기/가져오기 | 계획 승인 대기 |
| Phase 2 | Firebase RTDB(별도 프로젝트) 에서 센서 온습도 읽기 (read-only 화면) | 보류 |
| Phase 3 | Arduino Nano ESP32 오픈소스 라이브러리 (MIT) + `database.rules.json` + README | 보류 |
| Phase 4 | 50×70mm 캐리어 PCB (KiCad) | 보류 |

Phase 1 데이터 모델에 `temp`, `humidity`, `source`(manual/sensor) 필드를 미리 둬서 Phase 2에서 구조 변경 없이 연결한다.

## 3. 계산 로직 (엑셀 원본 수식 그대로)

원본 시트 `성장일지` 분석 결과 (A1:G370, 366일치 행):

| 항목 | 원본 수식 | 웹앱 |
|---|---|---|
| 입력 셀 | B2 출생일(2026-07-20), B3 급여율(15%) | 설정 |
| 날짜 A | `A5=$B$2`, 이후 `+1` | 출생일부터 366일 자동 생성 |
| 일령 B | `A−$B$2` | 동일 |
| 체중 C | 입력 (≥0 검증) | 입력 |
| 변화량 D | `C − 직전 측정값` (C 공란이면 공란) | 동일 |
| 권장 급여량 E | `ROUND(최근 측정 체중 × 급여율, 2)`, 체중·급여여부 둘 다 공란이면 공란 | 동일 |
| 급여 F | `O/X/예정` 목록 | 동일 |
| 메모 G | 자유 입력 | 동일 |
| 헤더 D2~G2 | 현재 일령 / 현재 체중 / 누적 증가량 / 평균 일증체 | 홈 카드 |
| 조건부서식 | 오늘 행 `#FEF3C7`, 변화량<0 빨강 | 동일 |

### 다음 급여일 (원본에 없는 신규 로직)
1. `기준 = 마지막 급여 O 날짜`
2. `다음 급여일 = 기준 + 급여주기`
3. 그 이전에 `예정` 행이 미래/오늘에 있으면 그 날짜 우선
4. 결과가 오늘 이전이면 “오늘(지연 N일)” 표시

### 온습도 판정 (기본값, 설정에서 수정)

| 지표 | 🥶/🥵 위험 | 😐/😓 주의 | 😊 정상 |
|---|---|---|---|
| 온도 | <20 / >28 °C | 20~22 / 26~28 | 22~26 |
| 습도 | <40 / >85 % | 40~50 / 80~85 | 50~80 |

종합 이모지 = 두 지표 중 나쁜 쪽. 기본값은 **크리스티드 게코 가정**이며 종 프리셋으로 교체 가능.

## 4. 엑셀 내보내기 전략

1. 템플릿 xlsx 를 앱에 base64 로 내장 (원본 그대로).
2. ExcelJS 로 로드 → `B2`, `B3`, `C5:C370`, `F5:F370`, `G5:G370` 만 기록. 수식은 건드리지 않음 → 열 때 Excel 이 재계산.
3. **온습도는 두 번째 시트 `환경기록` 에 별도 추가** (첫 시트는 원본과 100% 동일 유지).
4. 파일명: `lizard_growth_log_YYYYMMDD.xlsx`.
5. 가져오기: 같은 구조의 xlsx 를 읽어 입력 열만 복원 (백업/기기 이전용).

## 5. 보안 · 개인정보

| 위험 | 대책 |
|---|---|
| 데이터 외부 유출 | Phase 1 은 **서버·DB·계정 없음**. 모든 데이터는 기기 `IndexedDB` 에만 저장 |
| 서드파티 추적 | 분석·광고·CDN·외부 폰트 전부 미사용. 라이브러리 자체 호스팅 |
| XSS | `Content-Security-Policy`(`default-src 'self'`, `connect-src 'self'`), `innerHTML` 금지(`textContent` 사용), 메모 입력 길이 제한 |
| 저장소 공개로 인한 노출 | 저장소에 실제 일지 데이터·이름·이메일 커밋 금지. 템플릿 xlsx 는 **빈 입력 상태**로 정리해 내장 (샘플 체중 2.6g 만 유지 여부 확인 필요) |
| 키/시크릿 | Phase 1 에 없음. Phase 2 도 Firebase Web API 키는 비밀이 아니므로 **RTDB 규칙으로 보호**(read: 인증 사용자 UID 한정) |
| iOS 저장소 삭제 | 홈 화면 설치 PWA 는 7일 미사용 삭제 대상 아님. 그래도 “마지막 백업 N일 전” 배지 + 주기적 엑셀 내보내기 권장 |
| 의존성 공급망 | ExcelJS 버전 고정 + SHA-256 기록, 저장소에 vendoring |

## 9. 실패 방지 체크리스트

1. **iOS PWA 는 반드시 Safari “홈 화면에 추가” 로 설치** — 설치 전 Safari 탭에서 쓴 데이터는 설치본과 저장소가 분리됨. 설치 후 엑셀 가져오기로 이관.
2. **엑셀 템플릿은 값 셀만 기록** — 수식 셀을 덮어쓰면 자동 계산 파손. 내보내기 후 LibreOffice 재계산 값을 원본과 대조해 검증.
3. **공개 저장소에 실제 일지 파일 커밋 금지** — `.gitignore` 에 `*.xlsx`(템플릿 제외) 추가.
